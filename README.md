# Train/inference mismatch in LLM RL

Where does the gap between the sampler's log-probabilities and the trainer's
come from, component by component, and what does each proposed fix cost?

- `mismatch/` corpus sampling, 23 scoring "views" across vLLM and transformers,
  metrics, attribution report, and a drop-in `MismatchMonitor`.
- `rl/` a single-GPU GRPO trainer colocated with an in-process vLLM engine,
  with the corrections under test (`none`, `tis`, `mis`, `icepop`, `seq_tis`,
  `vllm_old`) and the system fixes (fp16, fp32 head, batch-invariant kernels).
- `docs/PLAN.md` the question, stages and numeric gates; `docs/RESULTS_*.md`
  are generated by `mismatch/report.py`.

```
cp env.sh.example env.sh          # paths, interpreter, SLURM settings
make test                         # CPU tests, ~2 min
make measure MODEL=Qwen/Qwen3-1.7B  # stages 1-3 on one GPU
slurm/submit.sh --job grpo_none --gpus 1 --requeue -- scripts/04_grpo.sh none
```
